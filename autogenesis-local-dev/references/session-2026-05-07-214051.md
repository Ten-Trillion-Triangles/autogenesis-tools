## Bug Confirmed: Combined `./gradlew :server:run :server-extend:run` Fails

When both servers are started in ONE gradlew invocation, they attempt to bind in the same JVM process. Result:

```
ss -tlnp | grep -E "7070|9080"
LISTEN *:9080  ← game server OK
(no 7070)      ← server-extend FAILED to bind
```

server-extend (port 7070) silently failed to claim its ports. Only the game server (9080) succeeded.

## Fix: Separate Invocations, server-extend FIRST

```bash
# server-extend first (~45s startup)
./gradlew :server-extend:run --no-daemon &
# Confirm: ss -tlnp | grep 7070  → LISTEN *:7070

# game server second (~90s first run due to TPipe compilation)
./gradlew :server:run --no-daemon &
# Confirm: ss -tlnp | grep 9080  → LISTEN *:9080
```

**Critical:** server-extend must be started FIRST. The game server (9080) starts cleanly regardless of whether 7070 is already listening.
