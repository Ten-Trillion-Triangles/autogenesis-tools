## Bug Observations

### BUG #7 — Map Area is DARK VOID (REVISED)

**Previous report said "blue person icon" — this was wrong.**

**Actual finding:** The main content area (center panel) is a completely black/dark void. No map, no territory visualization, no character icons, no terrain rendering. The screenshot shows the center of the screen as an empty black rectangle.

**Evidence:** MiniMax VLM analysis of screenshot: "The main content area in the center of the screen is currently a **dark void** (a large, empty black rectangle). No map or graphics are visible."

**What this means:** The map rendering component is either broken, not implemented, or rendering behind something. The game history panel (left) works, the stat bar (top) works, the input field (bottom) works — but the map/territory visualization area is a black void.

**This is NOT the blue person icon bug** — it's a different manifestation. The underlying cause could be the same (icon/portrait rendering failure) or different (map canvas not initialized).

**To investigate further:** Start a fresh game and observe if map ever renders anything. Check browser console for WebGL errors or canvas initialization messages.

### BUG #4 — Writing UI Stuck (PARTIAL)

**Finding:** "Result: (Planning...)" text from Round 1 Lord Maple Tree turn DID persist in the Story tab after the turn resolved. However, when we reconnected the browser (navigating to the URL again), the "Result: (Planning...)" was gone — replaced by actual resolved text.

**Interpretation:** The writing UI was NOT permanently stuck. The "Planning..." placeholder text was visible mid-turn and was replaced when the turn completed. The observation window may have caught the UI during a transient state, not a stuck state.

**Need:** More turns to confirm — observe multiple turn resolution transitions to see if prior output persists incorrectly.

### BUG #5 — Reasoning [] in UI (CANNOT PROVE)

**Finding:** Cannot observe the reasoning panel mid-turn. Browser shows "Generating narrative..." status while TPipe is processing. The reasoning panel is not visible during this phase.

**What we know:** TPipe traces confirm reasoning IS being generated (trace files contain `reasoningRounds`). The issue is display-path only — whether the UI renders it as `[]` or shows actual content cannot be determined while the turn is processing.

**Need:** Intercept the browser state during a brief window between TPipe completion and turn resolution display. This window is very short (~1-2 seconds).
